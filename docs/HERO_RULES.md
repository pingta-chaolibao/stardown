# 红色、绿色与蓝色英雄

实现已确认的三种英雄：红色整列推、绿色自动单枚拉、蓝色方向输入被动交换。蓝色可正常行走但不能推拉。第十三关加入红 / 蓝双英雄，第十四关为红 / 绿双英雄，第十五关为蓝 / 绿双英雄；没有加入绿色拉英雄、紫色英雄或灰色转化。`hero_kind` 支持 `red` / `green` / `blue`，省略默认红色；前八关 JSON、解法和原视频保持原字节。

## 红色：整列推

红英雄走向相邻英雄或水晶时，沿该方向扫描紧密相连的混合整列；列末是可走空地才让英雄和整列各前进一步。数量没有硬上限。墙、边界、草丛或激活屏障挡住列末时，整步不改变世界、不计数、不生成撤销记录。背离水晶走不会拉动水晶。

## 绿色：自动只拉最近一枚

一次方向输入先检查英雄目的格。目的格必须可走且没有水晶；绿色不能推，即使前方水晶后面有空地也不能前进。目的格被墙、边界、草丛、屏障或水晶挡住时，英雄与后方水晶都保持原样。

目的格有效时，检查英雄旧位置减去移动方向的格子。如果那里恰有水晶，就让最近的这一枚进入英雄原位置；相连的第二 / 第三枚不跟随。没有后方水晶就是普通行走。侧向邻居不会被误拉；不需要额外拉动按键。一次输入英雄只移动一格，一次拉动记一步 / 一拉，推动统计始终为零。

`HeroRules` 只决定推 / 拉 / 交换能力，`GridState` 生成候选位置；位置与机关一次统一结算后才提交。绿色从板上拉走水晶可能使屏障恢复；绿色离板但水晶同时跟到板上会连续保持压力，没有中间恢复误杀。恢复压英雄死亡后只能撤销复活。用户已确认能量再现摧毁格内水晶；公共结算同次提交，Undo恢复水晶身份。

撤销快照保存位置、水晶身份、有效操作数、推动 / 拉动 / 交换次数、压力、屏障和生死。存活时重开恢复全部初始状态，切关清空历史、计数与角色界面；死亡时不能通过重开或切关复活。

第五关沿用第一关的 11 × 3 地形与两枚水晶初始坐标，但英雄是绿色、目标绘制为绿色。实际路径 `DRLLURRDRRUURRLLDRRURRDR` 为 24 步、8 拉、0 推；两枚水晶均参与。`tools/search_north_05.py` 独立检查了 740 个按占用位置去重的可达状态；Godot 回归另验证真实颜色身份、普通键盘入口与完整撤销。

第六关以 11 × 7、七枚水晶和单板屏障复用同一绿色能力，没有修改本规则。65 步 / 17 拉 / 0 推路线包含英雄踩板、拉紫晶接替板位、过门到目标；离板关闭后，屏障挡住前方移动时后方水晶也不动。详细坐标与路线见 [README.md](../README.md)，独立回放为 `tools/check_north_06.py`。

## 蓝色：方向输入触发被动交换

每次方向键 / WASD 或屏幕方向按钮输入，只查看该输入方向。有合法可见英雄 / 水晶时，优先与射线上第一个目标互换位置；没有目标才尝试正常走一格。不能推拉。不扫描另外三向，也不每帧重复扫描；长按、系统重复和同一物理键未释放前的重复事件不会再次行动。松开再按是一次新输入。

从相邻格沿输入方向扫描到边界。墙、草丛和激活能量格立即阻挡视线，消失的能量格不挡。遮挡后没有可见目标时，仍可走到英雄相邻的有效空地；相邻格也受阻则不动。有目标时不能选择只走一格来绕过交换。无需独立技能键，Shift 没有另一个操作模式。

用户验收例子：13=(1,1) 向下只走到 24=(1,2)，不会与右侧 26=(3,2) 交换；随后按右，英雄直接到 26，水晶到 24，不落脚 25=(2,2)。模型与真实 WASD、方向键、屏幕方向按钮均覆盖此例。

`SwapRules` 是独立数据规则：使用边界、视线阻挡和占用分类寻找首目标，生成保留目标类型 / 身份的交换计划。测试覆盖近英雄先于远水晶、近水晶先于远英雄，压力板 / 终点不是目标。`GridState` 从第十三关起支持稳定 ID 的多英雄，蓝人可交换另一名英雄或水晶；前十二关仍按单英雄运行。

`GridState.try_move` 在普通移动之前处理蓝英雄目标优先级；交换候选位置、压力、全局屏障和死亡统一结算后才提交一个历史快照。撤销一次还原两端位置、水晶身份、操作 / 交换统计、机关与生死。独立 hero-only 压板夹具验证屏障恢复压英雄死亡，死亡后只能撤销复活。用户已确认恢复能量摧毁所在格水晶，交换后如触发再现就删除该水晶，Undo完整还原。

第九关保持确认的 11×3 布局：蓝英雄 (1,1)，紫晶 (7,0)、蓝紫晶 (3,2)，四墙与第一 / 五关相同，绿色终点 (9,1)。重新独立搜索穷举 318 个可达身份状态，验证路线 `DRRUURRDR`：9 个普通方向输入，7 次行走、2 次自动交换、0 推拉。第 2 次交换下方水晶，第 6 次交换上方紫晶。全大写 UDLR 均表示方向输入，操作类型由当前视线决定；不宣称最优。

第十关沿用同一蓝英雄能力，11×7确认地图内仅一枚紫晶、一个黄板和一个能量格。独立搜索2,560个存活身份状态，54次普通方向输入、5次交换验证通关；第44步英雄压板、第45步交换由水晶接替、第52步过门。前九关规则、地图及原视频保留。

第十一关复用方向输入被动交换：九板全压后保持压力，英雄经主平台四次首目标交换到(5,1)，再隔已打开的绿色门与(10,1)橙晶交换。构造路线19次方向输入、5次自动交换，随后绕到终点，不是穷举或最优证明。绿色机关、橙晶 / 其他晶色及界外显示均不改变交换或压力规则，颜色不匹配。

第十二关继续被动交换，加入粉红水晶显示配色，不增加角色能力或颜色匹配。实际26次方向输入、7次自动交换路线由独立占用搜索找到，再按橙/紫/粉红身份与Godot规则校验；三晶最终分别在(1,4)/(3,4)/(5,4)。两处草丛挡移动和视线，所有既有角色规则保持。


## 多英雄：选中、被动移位与完整撤销

`heroes` 数组提供稳定 `id`、`kind` 和初始位置，`active_hero` 指定初始操作身份。C 按数组顺序循环；屏幕按钮相同。C 仅改变选择，不计步 / 操作，也不写撤销记录；不移动、不触发交换、不改变压力 / 屏障 / 生死。单英雄 C 是无操作。选择不进入世界快照。撤销恢复最近一次实际行动前的全部英雄、水晶身份、实际行动计数、压力、门和各自生死，同时保留用户当前选中的英雄；无历史时撤销也不改变选择。重开恢复初始选中与全部初始状态。

红英雄可推动英雄与水晶混合长列，不设数量上限，扫描到末端空地后原子提交。推到的蓝英雄不会自动交换；蓝英雄交换红英雄也不会让红英雄自动推。选中的身份不会因为位置互换而变化。绿色仍只自动拉最近一枚水晶，不拉英雄。

视图逐一绘制英雄。选中者有亮描边和脚下选择圈，非当前英雄仅压暗保留红蓝色相，没有灰度化。所有英雄都占格、压板和参与死亡判定。任意英雄死亡立即锁住全局移动、C、重开及切关，必须撤销使对应英雄复活；不能切到存活英雄绕开死亡。

第十三关目标 `all_heroes_on_exits` 要求所有存活英雄同时占满不同目标，不限定对应；水晶没有英雄目标资格。重新验证的路线为24次实际行动，另有3次不计数C选择事件，包含2次交换。独立构造回放与Godot模型检查完整路线，不宣称最短路线或穷举整个状态空间。


第十四关使用红 / 绿两英雄，同一 `GridState` 不增加机制。独立搜索与Godot验证35次方向行动、15次不计数选择、6次推、4次拉；红人实际推动一列紫晶与绿人，未选中的绿人不自动拉；后来绿人自动单拉紫晶接替压板，保持两道能量门同时开放。界面根据角色阵容显示推动 / 拉动计数，当前绿色身份、描边和脚下圈正确，非当前英雄保留原本色相。C不计数且不入撤销、Undo保留当前选择的修正继续生效。


第十五关用蓝 / 绿阵容复用同一核心：61实际行动、20免费选择、11拉7换。蓝交换目标包括绿英雄及粉 / 蓝紫水晶，三次英雄互换不发动未选中绿人的拉动。界面按阵容显示交换与拉动，没有推动标签。两板持续开门后，绿拉蓝紫晶接替近板，蓝绿隔能量互换，再分别到不同目标。C和Undo约定不改变。


第十六关为红 / 蓝协作，直接复用混合整列推动与方向首目标被动交换。正常路线15实际行动、3免费选择、3交换，含2次英雄互换及1次粉紫晶压板接替，不需要推动。合法侧路另测红推蓝人与水晶混合列、边界受阻原子性和一次Undo整体恢复；未选中蓝人被推动不发动交换。紫色目标只改变绘制，不传送、不改变通关条件。16个导航入口分两行，高亮和保留色相的约定不变。


第十七关同时使用红/绿/蓝三英雄，稳定ID与数组循环C直接复用同一引擎，非当前角色继续占位压板且被动位移不发动能力。66次实际行动、15免费选择，2推11拉3换；三英雄各占不同目标才胜利。动作后公共能量结算可以删除水晶，Undo恢复全部水晶身份和所有英雄生死，不撤销用户当前选择。没有新增角色能力、透墙视线或怪物玩法。
