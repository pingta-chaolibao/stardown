# 红色、绿色与蓝色英雄

实现已确认的三种英雄：红色整列推、绿色自动单枚拉、蓝色主动视线交换。蓝色可正常行走但不能推拉。没有加入绿色拉英雄、紫色英雄、灰色转化或多英雄关卡。`hero_kind` 支持 `red` / `green` / `blue`，省略默认红色；既有关卡 JSON、解法和原视频保持原字节。

## 红色：整列推

红英雄走向相邻水晶时，沿该方向扫描紧密相连的整列；列末是可走空地才让英雄和整列各前进一步。数量没有硬上限。墙、边界、草丛或激活屏障挡住列末时，整步不改变世界、不计数、不生成撤销记录。背离水晶走不会拉动水晶。

## 绿色：自动只拉最近一枚

一次方向输入先检查英雄目的格。目的格必须可走且没有水晶；绿色不能推，即使前方水晶后面有空地也不能前进。目的格被墙、边界、草丛、屏障或水晶挡住时，英雄与后方水晶都保持原样。

目的格有效时，检查英雄旧位置减去移动方向的格子。如果那里恰有水晶，就让最近的这一枚进入英雄原位置；相连的第二 / 第三枚不跟随。没有后方水晶就是普通行走。侧向邻居不会被误拉；不需要额外拉动按键。一次输入英雄只移动一格，一次拉动记一步 / 一拉，推动统计始终为零。

`HeroRules` 只决定推 / 拉 / 交换能力，`GridState` 生成候选位置；位置与机关一次统一结算后才提交。绿色从板上拉走水晶可能使屏障恢复；绿色离板但水晶同时跟到板上会连续保持压力，没有中间恢复误杀。恢复压英雄死亡后只能撤销复活。未确认的“屏障恢复遇水晶”仍显式报告，不发明处置规则。

撤销快照保存位置、水晶身份、有效操作数、推动 / 拉动 / 交换次数、压力、屏障和生死。存活时重开恢复全部初始状态，切关清空历史、计数与角色界面；死亡时不能通过重开或切关复活。

第五关沿用第一关的 11 × 3 地形与两枚水晶初始坐标，但英雄是绿色、目标绘制为绿色。实际路径 `DRLLURRDRRUURRLLDRRURRDR` 为 24 步、8 拉、0 推；两枚水晶均参与。`tools/search_north_05.py` 独立检查了 740 个按占用位置去重的可达状态；Godot 回归另验证真实颜色身份、普通键盘入口与完整撤销。

第六关以 11 × 7、七枚水晶和单板屏障复用同一绿色能力，没有修改本规则。65 步 / 17 拉 / 0 推路线包含英雄踩板、拉紫晶接替板位、过门到目标；离板关闭后，屏障挡住前方移动时后方水晶也不动。详细坐标与路线见 [README.md](../README.md)，独立回放为 `tools/check_north_06.py`。

## 蓝色：主动视线交换

普通方向键 / WASD 始终走一格，不自动交换；目的格有水晶时不能推，背离水晶走也不会拉。按住 **Shift 再按方向键 / WASD** 才主动发动交换，也可以使用棋盘下方“交换”一组四向按钮。普通移动按钮仍然只走路。角色界面明确显示“操作”和“交换”：一次成功行走或交换各计一次有效操作，交换另加一次交换计数；失败不计数、不写历史。

沿所选上下左右方向，从相邻格扫描到边界；墙、草丛和激活能量格立即挡住视线。消失的能量格可穿过视线。只选择该射线上第一个英雄或水晶，不可跨越近目标换远目标；空方向没有目标就保持世界不变。目标与英雄的位置直接互换，这是已确认技能，不是普通行走。

`SwapRules` 是独立数据规则：用地图边界、视线阻挡查询和占用分类查询寻找首目标，并生成保留目标类型 / 身份的互换计划。独立测试覆盖 hero / crystal 目标优先级，墙 / 草 / 能量遮挡以及目标点 / 压力板不作为目标。当前 `GridState` 仍只存一个英雄，因此实际关卡交换目标是水晶；没有虚构第二英雄或宣称已实现多英雄关卡。

`GridState.try_swap` 生成候选英雄 / 水晶位置，再统一结算压力、全局屏障和死亡，成功才提交一个完整历史快照；撤销一次恢复两端位置、身份、全部统计、机关与生死。配置为 hero-only 压力的独立夹具覆盖交换后屏障恢复压英雄死亡、禁止移动 / 交换 / 重开 / 切关、仅撤销复活。恢复遇水晶仍沿用未定义行为保护，候选动作不提交，不把保护解释为用户确认的游戏规则。

第九关为确认的 11×3 单英雄长廊，蓝英雄 `(1,1)`，紫晶 `(7,0)`、蓝紫晶 `(3,2)`，四墙与第一 / 五关相同，绿色终点 `(9,1)`。合法路线 `DrRUUrRDR` 共 9 次操作：7 次走路、2 次主动交换；大写 UDLR 是走路，小写 udlr 是 Shift＋对应方向。第 2 次操作交换下方水晶，第 6 次交换上方紫晶；两次分别跨 2 和 3 格，最后正常走入终点。独立搜索保留水晶身份，共检查 20,412 个可达身份状态；不宣称最优。
