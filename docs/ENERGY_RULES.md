# 压力板与能量屏障

第三关按用户确认规则实现：英雄或水晶占据黄色压力板时，相连黄色能量块消失，不阻挡移动或视线；压力解除，能量块恢复。如果恢复格有英雄，该英雄死亡，此后只能撤销回到恢复前的状态复活。死亡时移动、重开、切关均不会改变世界或自动复活。

## 数据与结算

`energy_links` 是可选字段，前两关保持原数据；第三关定义如下：

```json
{"id":"yellow_01","plate":[1,1],"barriers":[[7,2]],"pressure_sources":["hero","crystal"]}
```

第六关直接复用单板格式：`plate=[9,5]`、`barriers=[[7,6]]`、压力来源仍为英雄或水晶；只有一个能量格，没有新增机制。正常路线第 29 步英雄占板，第 30 步紫水晶接替，压力连续保持，之后英雄通过能量格。真实输入回归另外验证离板关闭、移动 / 视线阻挡、闭门时不发生拉动，以及撤销恢复开门状态。死亡复活使用现有独立绿色机关夹具验证，不冒充本关正常通关画面。

每组显式声明唯一标识、压力板、一个或多个独占的关联屏障格，以及非空压力来源列表。占用谓词可配置为 `hero`、`crystal` 或两者；第三 / 四关两者均可触发。板与屏障都必须是内部地板，不能重叠；不同组不能共用板或屏障。

第四关按用户确认的 **三板 AND** 规则扩展，任一板未压住就保持 / 恢复屏障；第三关旧 `plate` 数据完全兼容且未改动。多板必须显式提供 `plates` 数组与 `activation=all`，不接受推测的 `any` 模式，也不能混用 `plate` / `plates`：

```json
{"id":"yellow_01","plates":[[1,4],[3,4],[5,4]],"activation":"all","barriers":[[6,1]],"pressure_sources":["hero","crystal"]}
```

`pressure_is_active(id)` 表示整组全部压住，`pressure_cell_is_active(id, cell)` 表示某块板的实际有效占用，`pressure_progress(id)` 返回已压住 / 总板数。画面分别点亮各块板，部分占用不会伪装成整组激活。

`GridState.try_move` 先检查当前墙体、边界、屏障与角色能力，再生成移动 / 红色整列推 / 绿色单枚拉的候选位置。`EnergyRules.settle` 统一计算所有压力与屏障，再判断死亡。只有结果完整可定义时才提交一个动作和一份撤销记录。同一步英雄与水晶接替压板会持续保持压力，没有中间恢复造成的误杀。绿色的拉动、计数和死亡同样一次撤销完整恢复，详见 [HERO_RULES.md](HERO_RULES.md)。

撤销保存并直接恢复玩家、水晶身份和位置、步数、推动次数、压力、屏障与存活状态，不依赖重新计算来补齐。存活时重开恢复完整初始快照；切关清空历史与机关状态。死亡优先于终点胜利。

`is_walkable(cell)` 检查静态地形与当前屏障；`blocks_sight(cell)` 查询该格是否阻挡地形视线；`sight_path_is_clear(cells)` 检查调用者给出的格子序列。激活屏障阻挡、消失后不阻挡。这里没有添加换位英雄、视野几何规则或将可移动目标当作墙的额外规则。

## 独立草丛类型

`bushes` 数组定义 `BushObstacle` 静态对象；它们与墙的地形和水晶身份分开。能力明确为不可移动、不可交换、阻挡移动、阻挡视线。英雄无法进入，单枚或整列水晶遇草丛均原子受阻，不改变计数或撤销历史。草丛不参与压力来源，也不会被撤销 / 重开转为水晶。没有实现灰色英雄或任何转换动作。

草丛坐标不能与英雄、水晶、目标、板或屏障重叠；只能位于地图内普通地板，不接受重复、墙内或越界数据。静态定义由关卡保有，动作只修改动态世界状态；切关载入独立草丛集合。

## 尚未确认的未来边界

**屏障恢复时水晶占格的行为没有得到用户确认。** 没有假定水晶被毁、穿墙或其他处置。独立测试场景若触及此未支持情况，返回 `rule_unresolved` 和具体诊断，候选动作不提交；这只是防止执行未定义行为的技术保护，不能当作已确认的游戏规则。将来地图需要该交互时，必须先确认规则。

该边界不阻塞第三关：实际 Godot 规则从本关初始状态穷举全部 **352 个合法世界状态**，没有任何状态的水晶位于 `(7,2)`，也没有触发 `rule_unresolved` 的转移；搜索保留最短触发路径以便出现问题时报告。此枚水晶要首次进入能量格，必须先让 `(1,1)` 的板持续受压，而本关仅有英雄和该枚水晶，两格横向相隔 6 格、纵向相隔 1 格；无法在同一步维持远处压力并将水晶推入能量格。

正常关卡视频只使用合法的第三关 21 步通关路径。死亡复活、恢复格水晶保护、压力接替和多机关等边界用明确标记的独立测试地图验证，不冒充本关可发生的流程。

第四关用 `tools/search_north_04.py` 独立穷举了 234,773 个存活占用状态，按玩家 / 水晶位置去重，不区分仅用于表现的水晶颜色；没有水晶进入能量格，也未发现未定义恢复转移。实际 34 步路线另由 Godot 按颜色身份和普通输入验证。第四关视频仅录该正常路线；三板释放导致死亡与单次撤销复活在独立夹具中验证，不替代实际通关。
