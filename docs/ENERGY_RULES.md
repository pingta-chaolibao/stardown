# 压力板与能量屏障

## 最新确认的全局规则（2026-10-23）

用户明确说明：**关卡内所有黄色压力地块必须同时被占据，所有黄色能量块才同时消失**，此时都不阻挡移动与视线；任意一块黄板解除压力，全部黄色能量块同时恢复。不是按各自独立组开门。英雄或水晶的压力来源、动作后统一结算，以及恢复压英雄死亡后仅可撤销复活，沿用已确认规则。

第七关单块黄色压力板 `(12,5)` 同时控制 `(12,1)/(15,4)` 两处能量块。用户确认修正版编号布局后，又检查二维转换并明确补正 `(0,2)` 为地板，即原 14 号 `(0,1)` 正下方；其余格保持原样，尤其 `(4,6)/(6,8)` 仍为墙。原编号 70 为 `(5,9)`、129 为 `(5,10)`。这一格补正使左侧绕行完整，152 步 / 56 次单拉路线已由独立搜索和 Godot 验证，没有更改拉动或机关规则。后续所有地图须先在原截图逐格编号：绿色可走、红色不可走、英雄 / 水晶 / 机制用蓝色标记，发用户确认和纠错后才录入；遮挡格明确标记为待确认。

**实现已对齐全局 AND。** `EnergyRules.settle` 先计算所有黄色压力地块的占用，再将同一个全局 AND 结果赋给全部黄色能量格；独立视频回放校验也使用此规则。专项覆盖所有三板占用组合在不同数据分组下结果一致、跨组压力交接、跨组恢复导致英雄死亡、完整撤销和原有未定义边界保护。第七关复用该实现，前六关地图与视频保持原样。

## 既有实现与已交付关卡

第三关按用户确认规则实现：英雄或水晶占据黄色压力板时，相连黄色能量块消失，不阻挡移动或视线；压力解除，能量块恢复。如果恢复格有英雄，该英雄死亡，此后只能撤销回到恢复前的状态复活。死亡时移动、重开、切关均不会改变世界或自动复活。

## 数据与结算

`energy_links` 是可选字段，前两关保持原数据；第三关定义如下：

```json
{"id":"yellow_01","plate":[1,1],"barriers":[[7,2]],"pressure_sources":["hero","crystal"]}
```

第六关直接复用单板格式：`plate=[9,5]`、`barriers=[[7,6]]`、压力来源仍为英雄或水晶；只有一个能量格，没有新增机制。正常路线第 29 步英雄占板，第 30 步紫水晶接替，压力连续保持，之后英雄通过能量格。真实输入回归另外验证离板关闭、移动 / 视线阻挡、闭门时不发生拉动，以及撤销恢复开门状态。死亡复活使用现有独立绿色机关夹具验证，不冒充本关正常通关画面。

第七关仍用单板格式，`plate=[12,5]`、`barriers=[[12,1],[15,4]]`。第 113 步英雄踩板，两门同时开放；114 步紫晶接替，115 步继续自动拉离黄板，两门同时恢复；123 / 124 步从另一侧重新交接，将紫晶留在板上，之后持续开放，149 步英雄穿过上方能量格。正常键盘测试另验证下方闭门阻挡，移动与视线查询检查两门同步。死亡 / 仅撤销复活沿用独立绿色夹具，不作为本关通关情节。独立搜索穷举本关 2,853 个存活位置状态，没有发现屏障恢复遇水晶的未定义转移。

第八关复用第四关的三板格式，`plates=[[1,4],[3,4],[5,4]]`、`activation=all`、`barriers=[[6,1]]`，但使用绿色英雄和三枚紫晶。第 51 步英雄与两枚水晶共同压满三板，52 步拉动第三枚紫晶接替；之后保持开门，55 步通过能量格。实际键盘另外验证离板恢复、撤销恢复开门和三处草丛受阻。独立 Python 与 Godot 都遍历 21,291 个存活占用状态，未发现水晶进入能量格或未定义恢复转移。所有原有关卡和核心规则保留，继续每关一份 JSON。

每组显式声明唯一标识、压力板、一个或多个独占的关联屏障格，以及非空压力来源列表。占用谓词可配置为 `hero`、`crystal` 或两者；第三 / 四关两者均可触发。板与屏障都必须是内部地板，不能重叠；不同组不能共用板或屏障。

第四关按用户确认的 **三板 AND** 规则扩展，任一板未压住就保持 / 恢复屏障；第三关旧 `plate` 数据完全兼容且未改动。多板必须显式提供 `plates` 数组与 `activation=all`，不接受推测的 `any` 模式，也不能混用 `plate` / `plates`：

```json
{"id":"yellow_01","plates":[[1,4],[3,4],[5,4]],"activation":"all","barriers":[[6,1]],"pressure_sources":["hero","crystal"]}
```

`pressure_is_active(id)` 仅报告该数据组的板是否全部被占据，`pressure_cell_is_active(id, cell)` 报告单板有效占用，`pressure_progress(id)` 返回局部已占据 / 总板数。这些是占用诊断，不决定独立开门；全部黄色能量块只取决于关卡所有黄板共同的 AND。画面按各板实际占用点亮，不能把局部已满误解为全局开门。

`GridState.try_move` 对蓝英雄先查本方向的合法首目标，否则检查普通目的格；随后生成移动 / 红色整列推 / 绿色单枚拉 / 蓝色方向输入自动交换的候选位置。`EnergyRules.settle` 统一计算所有压力与屏障，再判断死亡。只有结果完整可定义时才提交一个动作和一份撤销记录。同一步英雄与水晶接替压板会持续保持压力，没有中间恢复造成的误杀。绿色的拉动、计数和死亡同样一次撤销完整恢复，详见 [HERO_RULES.md](HERO_RULES.md)。

撤销保存并直接恢复玩家、水晶身份和位置、有效操作数、推动 / 拉动 / 交换次数、压力、屏障与存活状态，不依赖重新计算来补齐。存活时重开恢复完整初始快照；切关清空历史与机关状态。死亡优先于终点胜利。

`is_walkable(cell)` 检查静态地形与当前屏障；`blocks_sight(cell)` 查询该格是否阻挡地形视线；`sight_path_is_clear(cells)` 检查调用者给出的格子序列。激活屏障阻挡、消失后不阻挡。这里没有添加换位英雄、视野几何规则或将可移动目标当作墙的额外规则。

## 独立草丛类型

`bushes` 数组定义 `BushObstacle` 静态对象；它们与墙的地形和水晶身份分开。能力明确为不可移动、不可交换、阻挡移动、阻挡视线。英雄无法进入，单枚或整列水晶遇草丛均原子受阻，不改变计数或撤销历史。草丛不参与压力来源，也不会被撤销 / 重开转为水晶。没有实现灰色英雄或任何转换动作。

草丛坐标不能与英雄、水晶、目标、板或屏障重叠；只能位于地图内普通地板，不接受重复、墙内或越界数据。静态定义由关卡保有，动作只修改动态世界状态；切关载入独立草丛集合。

## 尚未确认的未来边界

**屏障恢复时水晶占格的行为没有得到用户确认。** 没有假定水晶被毁、穿墙或其他处置。独立测试场景若触及此未支持情况，返回 `rule_unresolved` 和具体诊断，候选动作不提交；这只是防止执行未定义行为的技术保护，不能当作已确认的游戏规则。将来地图需要该交互时，必须先确认规则。

该边界不阻塞第三关：实际 Godot 规则从本关初始状态穷举全部 **352 个合法世界状态**，没有任何状态的水晶位于 `(7,2)`，也没有触发 `rule_unresolved` 的转移；搜索保留最短触发路径以便出现问题时报告。此枚水晶要首次进入能量格，必须先让 `(1,1)` 的板持续受压，而本关仅有英雄和该枚水晶，两格横向相隔 6 格、纵向相隔 1 格；无法在同一步维持远处压力并将水晶推入能量格。

正常关卡视频只使用合法的第三关 21 步通关路径。死亡复活、恢复格水晶保护、压力接替和多机关等边界用明确标记的独立测试地图验证，不冒充本关可发生的流程。

## 第十三关的多英雄占用与生死

压力占用查询使用全部英雄，包含非当前操作英雄。候选移动 / 推列 / 英雄互换先同时更新所有对象，再结算全局压力，避免板上交接时发生中间闭门。C 只换选中身份，不改变占用或机关。

屏障恢复会分别检查所有英雄；任一英雄在恢复格内就死亡，同时锁定全局操作。撤销恢复全部英雄位置、每名英雄生死与完整机关状态，并保留用户当前选中身份。专项夹具验证未选中蓝英雄被屏障恢复压死，C / 重开 / 移动 / 切关不能绕过，一次撤销才恢复；正式第十三关录像只使用合法存活通关路线，不混入夹具。


第十四关复用单黄板 `(9,3)` 控制 `(8,1)/(8,5)` 两门。绿英雄行动24踩板打开全部移动 / 视线，红英雄26通过上门；行动30绿英雄自动拉紫晶到板上，连续保持压力，无中间恢复，行动32绿色英雄通过下门。合法侧路另验证绿英雄在紫晶接替前离板，两门同时恢复，撤销同步复原且保持当前选择。死亡锁定与仅Undo复活沿用共用专项，不假造本关死亡过程。
