## 可解性与机制验证

先构造并用独立Python `tools/check_north_11.py` 校验以下合法路线，不宣称穷举状态空间或最优：

```text
LLLLLDDDDRDRRUURULD
```

19次普通方向输入、14次行走、5次自动交换、0推拉。第11步英雄进入(1,5)压满九板；第12–15步在板间交换到(5,1)，压力持续保持；第16步视线穿过已打开的门，与(10,1)橙晶交换，橙晶留在(5,1)继续压板。英雄之后上、左、下绕入(9,1)，第19步首次明确胜利。没有把跨过终点的交换射线当成通关。

Godot模型另校验每次方向首目标、交换两端身份、全部统计、全程生存和最终胜利。覆盖全部512种九板占用组合，只有九板同时受压才开门。把所有晶色改为紫色、机关改为黄色并去掉界外显示注解后，整条路线的动作结果和每个完整世界快照完全相同，验证颜色与界外注解没有规则效果。

实际地图另测试闭门遮挡橙晶但相邻空地仍可走、闭门阻挡移动 / 视线、任一板释放关门、一次撤销还原、板间交换连续保持压力、右平台完整底行和下方界外受阻，以及胜利撤销 / 重开和切关历史 / 显示隔离。输入覆盖WASD、方向键、屏幕方向按钮、长按 / 回声 / 重复事件和空闲帧。

已验证通关路线没有死亡。死亡后禁止行动 / 重开 / 切关、仅撤销复活，以及未定义屏障恢复遇水晶的保护，继续由既有蓝英雄与机关独立夹具回归覆盖；没有穷举本关全部可达世界状态，不声称未定义交互在整个本关不可达，也不把夹具当通关画面。
