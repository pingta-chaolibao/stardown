## 第九关确认布局与新增范围

用户确认编号原图及二维图后的 11 × 3 文本规格：蓝英雄 `(1,1)`；紫晶 `(7,0)`、蓝紫晶 `(3,2)`；四墙 `(3,0)/(3,1)/(7,1)/(7,2)`；目标 `(9,1)`；其他内格地板、外部阻挡。全部 33 格、初始角色和水晶身份 / 颜色逐项校验，地形与第一 / 五关相同。

每关一个 JSON，schema 1 不迁移；新增 `hero_kind=blue` 和纯表现色 `blue_purple`。普通方向 / WASD 只走一格，蓝色不能推拉；Shift＋方向 / WASD 或单独“交换”四向按钮才主动交换。统计显示有效操作数与交换数，行走 / 交换各记一次操作，失败不计数。九关导航适配两种窗口；棋盘保留布局来源提示。

`SwapRules` 独立处理边界内四向射线、首目标分类和交换计划，墙 / 草 / 激活能量格阻挡，消失屏障不挡，英雄 / 水晶为目标而压力板 / 终点不作为目标。独立分类测试验证近英雄先于远水晶、近水晶先于远英雄。当前世界仍只有一个英雄，实际关卡目标是水晶；没有扩展为多英雄关卡或宣称多英雄世界已实现。旧红推、绿拉与全局机关规则保留。

前八关地图、解法、MP4 / 回放共 32 份文件与 `2420193308921339202f4ea5abf21fd0e8df49c6` 逐字节一致。旧视频缺少的 swaps 字段按 0 兼容；旧解决路径大写 UDLR 仍是行走，新小写 udlr 明确表示 Shift 技能。

## 合法通关与原子性

独立搜索保留两枚水晶身份，遍历 **20,412 个可达身份状态**。验证路径 `DrRUUrRDR` 共 **9 次操作：7 次行走、2 次交换，0 推 / 拉**；不宣称最优。第 2 次从 `(1,2)` 换到 `(3,2)`，蓝紫晶回到 `(1,2)`；第 6 次从 `(4,0)` 换到 `(7,0)`，紫晶回到 `(4,0)`；最后正常走入 `(9,1)`。Godot 模型和正常 Shift / 方向输入分别执行到明确胜利。

交换生成候选两端位置，统一结算压力、全局屏障与生死，再写入一份完整历史。专项覆盖四方向首目标、近目标不能跳过、边界 / 无目标 / 非法方向、墙 / 草 / 开闭能量格、普通走路不自动交换且不推拉、重复输入、角色隔离、胜利撤销 / 重开及切关历史清除。

独立 hero-only 压力夹具验证交换后全局屏障恢复、压英雄死亡；死亡后走路 / 交换 / 重开 / 切关均不改变世界，一次撤销复活并恢复位置、身份、所有计数和机关。独立 crystal-only 夹具验证尚未确认的“恢复遇水晶”仍返回明确未定义诊断、候选交换不提交。夹具不截图或录为第九关通关。第九关本身没有机关，不借测试夹具冒充关卡情节。
